# PragmaticBot.Server

PragmaticBot(WinForms 봇)의 백엔드입니다. 봇이 쓰던 기존 서버(`claude.piontest.store`)를
대체하며, 봇 클라이언트가 호출하는 REST 30개와 SignalR 허브를 그대로 구현하고
관리자 웹 화면을 함께 제공합니다.

- ASP.NET Core 10 / EF Core 9 (Pomelo MySQL)
- MariaDB 10.4 (XAMPP) — `pragmaticbot` 스키마
- 기본 주소 `http://0.0.0.0:5080`

## 실행

```
dotnet run
```

첫 실행 시 마이그레이션이 자동 적용되고 관리자 계정이 시드됩니다.
관리자 화면은 <http://localhost:5080/Admin> 입니다.

### 설정

민감한 값은 `appsettings.local.json`(git 제외)에 두고 `appsettings.json`을 덮어씁니다.

| 키 | 설명 |
| --- | --- |
| `ConnectionStrings:Default` | MariaDB 접속 문자열 |
| `Jwt:Key` | 토큰 서명 키 (32자 이상) |
| `Jwt:LifetimeHours` | 토큰 수명 (기본 24시간) |
| `Seed:AdminUsername` / `Seed:AdminPassword` | 관리자가 하나도 없을 때만 생성 |
| `Kestrel:Endpoints:Http:Url` | 수신 주소 |

HTTPS 리디렉션은 의도적으로 꺼져 있습니다. 봇의 `ApiClient`는 JSON이 아닌 응답을
오류로 처리하므로, 307 리디렉션이 오면 사용자에게 엉뚱한 파싱 오류로 보입니다.
TLS가 필요하면 앞단에 리버스 프록시를 두세요.

## 봇 연결

클라이언트 `appsettings.json`의 `ApiBaseUrl`을 이 서버로 바꾸면 됩니다.

```json
{ "ApiBaseUrl": "http://127.0.0.1:5080/" }
```

## 조직 구조

계정은 **본사 → 총판 → 대리점 → 회원** 4단계로 이어집니다. 회원만 봇을 돌리고,
나머지는 관리 화면에 로그인해 자기 산하를 관리합니다.

| 등급 | 만들 수 있는 계정 | 볼 수 있는 범위 | 도메인·게임·공지 |
| --- | --- | --- | --- |
| 본사 | 총판 · 대리점 · 회원 | 전체 | 가능 |
| 총판 | 대리점 · 회원 | 자기 산하 | 불가 |
| 대리점 | 회원 | 자기 산하 | 불가 |
| 회원 | — | — (관리 화면 로그인 불가) | 불가 |

범위는 `Users.TreePath`(예: `/1/3/5/`)로 판정합니다. 자기 경로로 시작하는 행이 곧 산하이므로
대시보드·배팅내역·로그·사용자 목록이 전부 한 가지 규칙으로 걸러집니다. 조직을 옮기면
(`소속 이동`) 하위 경로도 함께 다시 씁니다.

상위가 하위를 끄면 그 산하 봇 세션이 전부 즉시 종료됩니다. 자기 자신과 같은/상위 등급은
변경할 수 없고, 하위 조직이 남은 계정은 삭제되지 않습니다.

## 관리자 화면

| 페이지 | 하는 일 | 접근 |
| --- | --- | --- |
| 대시보드 | 산하 총판·대리점·회원 수, 접속 중 회원, 오늘 배팅/손익, 최근 오류 | 전 등급 |
| 조직 · 사용자 | 조직도, 계정 생성, 만료일·활성 여부, 비밀번호 변경, 강제 로그아웃, 소속 이동, 삭제 | 전 등급 (산하만) |
| 배팅내역 | 조직·회원·기간·결과 필터, 합계와 승패 집계 | 전 등급 (산하만) |
| 로그 | 봇이 올린 로그 조회 (정리는 본사만) | 전 등급 (산하만) |
| 도메인 | 프로바이더별 기본 도메인·WebSocket·잔액 셀렉터, 사용자별 슬롯 현황 | 본사 |
| 게임 | 봇 "룸 설정"에 나오는 바카라 테이블 목록 | 본사 |
| 공지 | 봇 상단에 표시되는 공지 | 본사 |

본사 전용 화면은 메뉴에서 숨겨질 뿐 아니라 GET은 `RequireOwner()`가, POST는
`[OwnerOnly]` 필터가 막습니다. URL을 직접 쳐도 통과하지 않습니다.

## 동작 규칙

**단일 로그인.** 계정마다 세션 하나만 유효합니다. 새 기기가 로그인하면
`Users.CurrentSessionId`가 갱신되고, 이전 기기는 다음 하트비트(10초 주기)에서
`409 Conflict`를 받아 스스로 종료합니다. 동시에 SignalR로 `ForceLogout`을 보내
즉시 반응하게 합니다.

**강제 로그아웃.** 관리자 화면의 버튼, 계정 비활성화, 비밀번호 변경이 모두
`ForceLogout`을 발송합니다.

**오류 응답 형식.** 봇은 실패 응답 본문을 `{"message": "..."}`로 파싱합니다.
상태 코드별로 의미가 정해져 있으니 지켜야 합니다.

| 코드 | 봇 쪽 처리 |
| --- | --- |
| 401 | `ApiUnauthorizedException` — 로그인 화면에서는 "실패"로 표시 |
| 400 | `ApiBadRequestException` |
| 409 | `ApiSessionConflictException` — 세션 종료 |
| 404 | 일부 조회는 "설정 없음"으로 정상 처리 (룸 쿨다운, 전략 체인, 방게이트 서식) |

## 데이터 범위

프로바이더 도메인 설정(`DomainSettings`)과 게임 목록(`Games`), 공지는 운영자 단위로
공유됩니다. 그 외 서식·배팅금액·행렬·한도·전략 체인·사이트 슬롯·배팅 기록은
모두 사용자별입니다.

## 계약 주의

`Contracts/Dtos.cs`는 클라이언트 `PragmaticBot/Models/Api/ApiDtos.cs`와 필드 단위로
일치해야 합니다. 클라이언트는 camelCase + 대소문자 무시로 역직렬화하므로 **멤버 이름이
곧 계약**입니다. 한쪽만 이름을 바꾸면 값이 조용히 null로 들어갑니다.

## 스키마 변경

```
dotnet dotnet-ef migrations add <이름>
```

`dotnet-ef`는 이 프로젝트의 로컬 도구로 설치되어 있습니다(`.config/dotnet-tools.json`).
마이그레이션은 서버 기동 시 자동 적용됩니다.
